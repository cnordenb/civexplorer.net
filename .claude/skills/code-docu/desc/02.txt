@ js/script.js
Where the page starts: its top-level code runs once, `RUNS` says what the page does in each of its modes, and start()
  starts the parts of the page in their order. It never touches the page itself.
- [Start-up 23-25]: Sets the screen's pictures once (startScreen()), then Simple UI from the saved setting, so pictures
  load at once or never. Loads data.json, then has useAndLoadLanguages() load the languages, run() start the page,
  and failLoad() show the load error if loading fails. What each step does depends on the mode, which line 11 reads
  once from the address (`MODE`): `?test`, `?update` or neither.
- RUNS: What each mode does, `?test`, `?update` or the page alone: which languages to load, what to run once the page
  is up, and what to do if data.json cannot load. `?test` loads every language, runs the tests (runTests()) and, if
  loading fails, marks them failed (loadFailed()), so CI never waits for a result that cannot come; `?update` loads
  the visitor's language and runs the updater (runUpdate()), which loads the others itself.
- useAndLoadLanguages: Reads data.json (useData()) and loads the languages the mode needs: every one for `?test`,
  else the visitor's. Runs once, when data.json has loaded.
- loadPreferred: Loads the visitor's language, preferredLanguage(), and goes on without it if it cannot be loaded: the
  page then starts in English, and start() opens the popup that says so. A visitor downloads only the language shown.
- run: Starts the page (start()) and its pictures (startPictures()), lets the loading screen go once every picture has
  loaded (hideLoadingWhenReady()), and runs what the mode runs: the tests, the updater or nothing. Runs once, when
  data.json and the languages have loaded.
- failLoad: Shows that the page could not load: hides the loading screen, shows `#loadError` and, with `?test`, marks
  the tests failed. It sees only a failure to load data.json or, with `?test`, a language, not an error of the page
  or the tests, and throws the error again, so that it shows in the console.
- start: Starts the page: gives the model the start language (startLanguage()), the visitor's or, when it could not
  be loaded, the first, and the model reads its saved Include settings itself; starts the controllers of the tree and
  of the Options window, writes the fixed texts, has the page observe the model, draws it once with `redraw("start")`
  and reveals it. If the visitor's language could not be loaded, it then opens the popup `#languageError`
  (showLanguageError()). Runs once, from run().
- testRunner: Loads run_test.js, the tests, only when `RUNS` asks for them, so the page alone never downloads them.

@ js/model/civsets.js
Sets of civilisations: each civilisation is one bit, so a set of civilisations is a single number that `&` and `|`
  combine quickly, and `allCivs` is the set of every one. It imports nothing: useData() hands it the civilisations.
- useCivs: Takes the civilisations of data.json and gives each one bit, in their order, and makes `allCivs` from them.
  Runs once, when data.json has loaded.
- bit: Returns a civilisation's bit, or stops with an error for an unknown name, so a typo in data.json cannot silently
  drop a civilisation.
- size: Counts the civilisations in a set by counting its bits. Behind every number on the page.
- setOf: Turns an availability rule from data.json (`"all"`, a `has` list or a `lacks` list) into a set. Rules stay
  short in the file while the code works with sets.
- civsOf: Turns a set back into a list of civilisations, in data.json order. Used to list the civilisations that fit.

@ js/model/texts.js
The chosen language: its text, its language tag, and how it sorts, counts and writes numbers, with the functions that
  put names and counts into words in it. Everything that shows, sorts or counts text reads it. `PLACEHOLDER`, the
  pattern of a placeholder such as `{n}`, is exported too, so that fill() and compose() in toolkit.js find
  placeholders alike.
- useLanguage: Switches the active language: its text, language tag, sorting, plural rules and number format. Everything
  that shows, sorts or counts text reads these, so one call changes them all.
- nameOf: Returns a tree item's or group's name in the current language, or its key if missing. Used wherever an item is
  shown or searched.
- civName: Returns a civilisation's name in the current language, or its key if missing. Keeps the civilisation list
  translated.
- plural: Picks the right form of a counted text, such as "1 civilisation" or "5 civilisations", by the language's
  plural rules, and fills in the formatted number.
- fill: Replaces `{name}` placeholders in a text with values, leaving unknown ones alone. All text lives in the data
  with placeholders, so the code never builds sentences itself.
- plain: Lower-cases a text and strips accents, spaces and punctuation, so Find matches names however they are typed, in
  any language.

@ js/model/icons.js
The icons' file names, the order of the pictures in an atlas, and where each item's icon is: facts about the data,
  which the views and the updater both need.
- fileName: Names a picture's PNG file from its number or name, such as `8.png`: the one place that knows the pattern,
  for iconFile() and byFile().
- iconFile: Returns the path of a tree item's icon PNG from its kind and picture number, such as
  `assets/images/icons/nodes/unit/8.png`, for the updater's report of new icons.
- civFile: Returns the name of a civilisation's icon file: its name in lower case, unless `icons.names` in data.json
  gives another, such as `inca` for the Incas.
- byFile: Sorts picture numbers or names as their PNG files sort by name, `1.png`, `10.png`, `100.png` and on to
  `11.png`, which is the order of the cells in an atlas: a fact about the data, which cellOf() and iconsFor() in
  updater.js both use.
- spriteOf: Returns an item's sprite, its kind and its picture: a group's from `icons.groups` in data.json, any other
  item's from `pictures`. The tree view finds an icon through it and atlasOf(), so it never reads data.json itself.
- atlasOf: Returns the pictures of a kind's atlas, from `icons.atlas` in data.json, in which cellOf() finds a cell.
- cellOf: Finds a picture's cell in its atlas, which holds the pictures in file-name order, row by row, with as many
  columns as the square root of their number, rounded up. The order is worked out once per list. It stops with an
  error for a picture that is not in its atlas, as the page would otherwise quietly show a cell outside it. The
  civilisations' atlas is in the order of their icons' files, so for a civilisation it is given civFile().

@ js/model/itemtree.js
Builds the tree's items from data.json: what Include and Include Regionals hide, the rows a variant borrows from the
  items it stands in for, each item's branch set, the civilisations that have it and everything under it, and the
  copies, rivals, opponents and alternatives. It owns `items` and `roots`, which model.js passes on, so the imports go
  one way and every other script imports them from model.js.
It also answers the questions about the tree's shape, which need no marks: an item's line of upgrades, the items under
  it in a chain, the items above and below it, and whether it counts as a unit or technology.
- buildItems: Builds the items afresh from data.json and the tree's settings, `{ include, regional }`: lends the
  variants their rows, leaves out what Options leaves out, turns the rest into items, stores their branch sets, and
  links copies, rivals and alternatives. rebuild() in model.js runs it and keeps the marks.
- reachOf: Returns an item's reach in data.json, `"common"`, `"regional"` or `"unique"`, or nothing for a group. The
  one place that reads it, for pruning, for lending and for isUnique() in model.js.
- withBorrowedKids: Adds under every item that names items it stands in for the rows those items lend, in the order
  named, so their technologies are written only once in data.json.
- placesIn: Lists every node of data.json's tree once, top to bottom, each with whether it lies inside an item or a
  group of lines. borrowedKids() looks an item up in it.
- placesBelow: Lists the nodes under a place in the tree for placesIn(), top to bottom, each with whether an item or a
  group of lines lies above it.
- treeKeys: Lists every item (or group) name in a tree, top to bottom. Used to check the tree, to find groups that need
  text, and by the updater to know which items to look up.
- borrowedKids: Finds the item that a `"replaces"` names and returns the rows it lends; none if it is not in the tree
  or counts as a unit or technology, as its rows are then its own upgrades.
- lentCopy: Copies a row and the rows under it that can be lent, marked as copies, for an item that stands in for it.
- isLendable: Tells whether a row can be lent to an item that stands in for its own: neither unique nor marked `"own"`.
- keysIn: Turns a `"replaces"` or `"excludes"` value, one name, a list or nothing, into a list.
- prune: Leaves out what Options leaves out: the unique groups and unique items (keeping their rows), regional items
  without Include Regionals, and items that one, all or all but one civilisation have, unless something under them is
  shown.
- isHidden: Tells whether Options hides a node and everything under it: a unique group without Include Unique and
  Universal, or a regional item without Include Regionals.
- ownerCount: Counts the civilisations that have an item, from its rule in data.json; none for a group.
- tellsNothing: Tells whether an item tells nothing about who fits, as one civilisation, all or all but one have it.
- isBareLeaf: Tells whether a node is left out because nothing under it is shown: always for a group, and for an item
  that tells nothing (tellsNothing()) without Include Unique and Universal.
- liftedKids: Hands the rows of a unique item that is left out to its place, noting the item in their path, so that
  without the Camel Scout the Camel Rider is a row of the Stable. Lent rows are dropped.
- collect: Turns the shown part of data.json's tree into the items the page uses (newItem()), top to bottom, and notes
  on each whether it is a unit or technology. Stops with an error for an item without availability.
- newItem: Makes one item: its key, a path that tells copies apart, its set of civilisations (all, for a group), and
  room for its mark, its branch set and its links, which the steps after collect() fill in.
- inUnitOrTechLine: Tells whether an item is a unit or technology: an item with another item, or a `"lines"` group,
  above it. Worked out once, as the item is made, for isUnitOrTech().
- storeBranchSets: Stores each item's branch set in `item.all`, walking the items from the last to the first, so the
  rows' sets are ready before the item above them needs them. A row's count of matching civilisations uses it.
- branchSetOf: An item's branch set: the civilisations that have it and, by their branch sets, everything under it.
- linkOriginals: Links every copied item to its original, the item of the same key that is not a copy, so that model.js
  can share their marks (shareMarksWithOriginals()).
- linkRivals: Links the items that `"excludes"` names as rivals, both ways, and gives every item the opponents its
  rival's branch holds (addOpponents()).
- linkAlternatives: Links the items that `"replaces"` names as alternatives, both ways, and adds the other items that
  stand in for the same (addSiblingAlternatives()).
- linkBothWays: Links items both ways by `"excludes"` or `"replaces"`, as rivals or as alternatives.
- addOpponents: Gives every item the opponents that its must have greys out: everything on its rival's branch, and the
  other way round.
- opposeBranches: Gives everything on an item's branch the whole of its rival's branch as opponents, each branch
  without the other. The rival's branch is worked out once, not once for every item on the item's.
- branchWithout: An item and everything under it, but its rival and what is under that, so the Stable's branch leaves
  out the Xolotl Warrior inside it.
- addSiblingAlternatives: Adds to the alternatives of an item that stands in for others the other items that stand in
  for the same, so marking the Folwark greys out the Settlement too.
- lineOf: The whole line of upgrades an item is on, from its top to its end, or just the item if it is on none. Filters
  names and clears lines with it.
- endsInLine: Tells whether an item's chain (itemChain()) ends a line of upgrades: the item is no group, and the chain's
  last item has nothing under it, so the line neither forks nor goes on into a group.
- lineEnd: The last item of an item's chain (itemChain()): the end of its line of upgrades, unless the line forks or
  goes on into a group first. endsInLine() tells which.
- chainOf: An item and the rows below it for as long as each has exactly one row under it. Marking opens these.
- itemChain: An item and the items below it for as long as each has exactly one row under it and that row is not a
  group. passedTo() and lineEnd() follow it.
- chainWhile: An item and the rows below it for as long as each has exactly one row under it and that row is taken by
  the test it is given. chainOf() and itemChain() are made with it.
- isUnitOrTech: Tells whether an item is a unit or technology, as collect() noted on it (inUnitOrTechLine()). Buildings
  and groups mark everything in them; units and technologies pass marks along lines.
- ancestors: The items above an item, from its parent up to the top. Find opens them to bring a found row into sight,
  and inUnitOrTechLine() reads them.
- descendants: Everything under an item, at every depth.

@ js/model/updater.js
The updater, which `?update` runs: it fetches aoe2techtree.net's data, trees and texts and its page, works out the
  civilisations, who has what, the icons, every name and the game update, compares them with data.json and writes the
  new files. It reads files only through load() in datahandler.js. The game's nodes and the `extras` of data.json are
  read into one shape (fromGame(), fromExtra()), an Adapter, and the trees and texts are kept in maps keyed by
  civilisation and language.
- fetchUpdate: Loads every language of the page, has fetchUpstream() download aoe2techtree.net's data, trees, texts and
  page, runs refresh(), and returns what report.js shows: the report's lines, whether the tree blocks the update, the
  numbers of civilisations, items and languages, and the files that changed, data.json always. So a game update needs
  only a browser.
- fetchUpstream: Downloads aoe2techtree.net's data first, as it names the civilisations, sorted here once, then the
  tree of every civilisation, the game's texts in every language of the page and its page, all at once.
- keyedBy: Fetches one file for each civilisation or language, all at once, and keeps them in a map by its key.
- countsOf: Counts the civilisations, items and languages of the new data, for the report's last line.
- changedFiles: Splits the current and the new data into their files (pack()), writes each as data.json is laid out
  (toJson()), and keeps the new files that differ from the current ones, and data.json always.
- refresh: The updater's core: from the current data and what fetchUpstream() fetched, it works out the civilisations,
  who has what, the icons and every name from aoe2techtree.net's data and the extras, takes the game update from its
  page (gameUpdate()), and writes the report. Stops if treeProblems() finds an unknown item, or one named twice.
- gather: The updater's first step: reads aoe2techtree.net's trees into three tables (fromTrees()) and adds the items
  of `extras` in data.json to them (fromExtra()). Lists any extra that aoe2techtree.net now has itself, for the report,
  so it can be taken out of `extras`.
- fromTrees: Reads aoe2techtree.net's tree of every civilisation into three tables: each item's node, in the updater's
  shape (fromGame()), the civilisations that have it, and how often each of its pictures is used.
- fromGame: Turns a node of aoe2techtree.net's trees into the updater's shape: its name, the numbers of its name and
  help texts, its kind, its reach (common, regional or unique), its picture, and whether the civilisation has it.
  With fromExtra(), the rest of the updater reads one shape, wherever an item comes from.
- fromExtra: Turns an entry of `extras` in data.json, an item aoe2techtree.net gives to no civilisation, into the node,
  owners and picture counts the updater gathers for every other item, the node in the shape fromGame() gives. A test
  checks the extras the same way.
- capitalise: Upper-cases the first letter of a text, as some names in the game start in lower case.
- treeProblems: Lists what stops the updater, for its report: the items the tree names twice, in alphabetical order,
  then those that aoe2techtree.net does not have.
- freshData: Makes the new data: a copy of the current one with aoe2techtree.net's civilisations, and who has each item
  of the tree (availabilityOf()) and its icon (pictureOf()).
- availabilityOf: Writes who has an item in its shortest form: `"all"`, a `has` list or a `lacks` list. Keeps data.json
  small; a test checks that every rule is stored this way.
- pictureOf: Picks an item's icon for data.json from aoe2techtree.net's data: its kind, the picture most civilisations
  show, and whether it is common, regional or unique, which the outlines and Include Regionals use.
- iconsFor: Adds every new picture to a copy of the list of its atlas in `icons.atlas`, in file-name order, and lists
  it for the report with its PNG, so the atlas can be built again.
- translated: Works out every civilisation's and item's name in every language from the game's texts, unless an
  override says otherwise, writing out abbreviated names from the help text, and returns the new data's texts with
  them.
- joinLines: Joins a game text broken with `<br>` into one line, by the language's rules for spaces and hyphens, and
  tidies spaces. The game breaks names to fit its buttons.
- isLower: Tells whether a character is a lower-case letter. joinLines() uses it to tell a hyphenated word from a real
  hyphen.
- localName: Finds an item's name in a language's game texts. If that name looks abbreviated, it takes the bold name
  from the item's help text instead, which is written out in full.
- gameUpdate: Reads the game update from aoe2techtree.net's page: the number after "Update" and the address of its
  notes, which its link leads to and the footer links too. A new number goes into the report; if the page has none,
  the report says so and data.json keeps the update it had.
- civChanges: Lists the civilisations added or gone, for the report.
- availabilityChanges: Lists the items of the tree whose civilisations changed, for the report.
- unowned: Lists the items of the tree that no civilisation has, for the report.
- renames: Lists the civilisations and items renamed in each language, for the report. A name that was not there before
  is new, not renamed.
- unplaced: Lists the items aoe2techtree.net has that are not yet in the tree, in alphabetical order, for the report,
  leaving out those that `ignore` in data.json names.
- missingText: Lists, per language, the page texts and group names that are missing. A test and the updater's report use
  it, so no language shows a blank.
- toJson: Writes JSON the way data.json is laid out: short objects and lists on one line, the rest indented, and a list
  that ends an object of scalars opened on the object's line. Keeps the updater's files readable and their changes easy
  to review.
- isScalar: Tells whether a value is text, a number, true or false, or null. Helps toJson() decide what fits on one
  line.
- isFlatList: Tells whether a value is a list of scalars only, which toJson() writes on one line.
- oneLine: Writes a value as one line of JSON, with a space after each comma and colon. The building block of toJson().

@ js/model/model.js
The marks and their rules: how marks pass on, what is greyed out, which civilisations fit and how many, and what
  Filters shows, with Include, Include Regionals and the language, which it saves itself. itemtree.js builds the items;
  model.js passes them on with the questions about the tree's shape, so every other script imports them from here.
It is the subject of the Observer pattern: only its own functions change it, and each then tells its observer,
  page.js, what changed. It never touches the page.
- subscribe: Adds an observer, which notify() then calls after every change. Only page.js subscribes (Test 255), and it
  never leaves, so there is no `unsubscribe`.
- notify: Tells every observer what kind of change was made, once and as soon as `matching` is up to date: `"marks"`,
  `"tree"` or `"language"`. The observers read the rest from the model themselves. It is the model's own (Test 256), so
  nothing else can announce a change.
- startModel: Takes the language, reads the saved Include settings (recallSetting()), and builds the tree once, saving
  nothing and telling no one: the page is drawn afterwards, all at once, with `redraw("start")`. Runs once, from
  start().
- setInclude: Turns Include Unique and Universal on or off, and has saveAndRebuild() save the choice, build the tree
  again, keeping marks, and tell the page that the tree changed.
- setRegional: Turns Include Regionals on or off, and has saveAndRebuild() save the choice, build the tree again,
  keeping marks, and tell the page that the tree changed.
- saveAndRebuild: Saves a setting of the tree (rememberSetting()), builds the tree again, keeping marks, and tells the
  page that the tree changed. What setInclude() and setRegional() share.
- setLanguage: Makes a language the one the tree's names are in, saves the choice, has keepInAddress() put it in the
  address (`?lng=`), so a shared link keeps it, and tells the page that the language changed.
- rebuild: Has buildItems() build the items afresh from data.json and the Include settings, keeps every mark by its
  path, shares the marks of copies with their originals, and works out `matching` again (updateMatching()). Runs at the
  start and whenever an Include setting changes.
- shareMarksWithOriginals: Ties every lent row to the original that linkOriginals() found, so both share one mark:
  marking Two-Man Saw under the Mule Cart marks it under the Lumber Camp too, with one entry in Filters. The copy reads
  and writes its mark, `self`, through its original, a Proxy for one property.
- updateMatching: Works out the civilisations that fit every mark, as `matching`.
- toReveal: The rows a mark will reach, or none if it clears the item or the item is greyed out. The controller opens
  the way to them before it marks, so they come into sight before the greyed-out branches close (Req. 28, 31).
- toggleMark: Marks an item must have or must lack, or clears it if it already has that mark, passes must have up to its
  prerequisites, works out `matching` again and tells the page that the marks changed. A greyed-out item is left as
  it is, and no one is told (Req. 37).
- clear: Clears every mark (Req. 17), works out `matching` again and tells the page that the marks changed.
- unmarkLone: Clears the must have of a unique item whose lone filter entry is cleared, and only that, and tells the
  page that the marks changed.
- unmarkLine: Clears what an entry of Filters stands for: the marks of its kind along its line, or the item and
  everything in it, keeping the lone filter entries (keepingLoneFilters()), and tells the page that the marks changed.
- keepingLoneFilters: Makes a change, then gives back its must have to every unique item that had a lone filter entry
  before it, so clearing a line or a building keeps those entries (Req. 36).
- marksChanged: Works out `matching` again with updateMatching() and tells the page that the marks changed. Every
  change of the marks ends with it.
- barred: Tells whether an item is greyed out: not marked must have itself, while one of its alternatives or opponents
  is (Req. 37).
- toggleState: The mark an item has now, which toggleMark() sets or clears: its own for a unit or technology, otherwise
  what all of it shows (branchState()).
- spreadOf: The rows a mark reached, which marking opens: down to the first fork, and the rows it passed to or
  everything inside.
- applyMark: Sets or clears a mark: on everything in a building or group, or along a unit's or technology's line. Must
  lack also clears must have below that depended on it.
- setMark: Marks an item and everything under it, groups only through their rows, skipping the rivals of the item
  marked. How a building or group is marked or cleared.
- setMarkUnder: Does the work of setMark(): marks an item and, row by row, everything under it but the rivals of
  `top`, the item that setMark() was given.
- passedTo: The items a mark passes down to: along the item's line until it forks, and only those the same civilisations
  have (Req. 29, 30).
- prerequisites: The units and technologies above an item that its must have passes up to, stopping at a building or at
  an item that some civilisations with it lack (Req. 34).
- covers: Tells whether every civilisation that has an item also has the one above it, so that must have may pass up to
  it.
- behind: Tells whether an item lies inside a closed greyed-out item, where Find does not look.
- locked: Tells whether a greyed-out item is also closed: unless its own rival is inside it, as the Xolotl Warrior is
  inside the Stable, which stays open so the Xolotl Warrior stays in sight.
- isInside: Tells whether an item lies anywhere under another.
- branchState: The mark a branch shows: the one an item's own mark and all its rows share, or `"mixed"` when they
  differ, leaving out the rivals of the item asked about.
- stateUnder: Does the work of branchState(): the mark that an item and every row under it share, or `"mixed"`,
  leaving out the rivals of `top`, the item asked about.
- checkboxState: What a row's box shows: a unit's or technology's own mark, or a dash if a row below has another;
  otherwise branchState().
- countOf: The two counts beside an item's name, `withItem` and `withBranch`: the civilisations that fit the marks and
  have the item, or for a group everything in it, and those that fit and have the item and everything under it, its
  branch set. The tree's view shows one or both.
- matchingCivs: The civilisations that fit every mark, for the list on the right.
- filtersOf: Works out the entries of Filters, in the tree's order: the lone filter entries (loneFilters()), and one
  entry per marked building, group or line (markedFilters()), but none for what a marked row above covers, and only
  one for each line and mark (topFilters()).
- loneFilters: The lone filter entries: one for every unique item that is not a copy and whose must have keeps its
  own entry (keepsOwnFilter()), so it stays named in Filters while its line or group is marked too (Req. 36).
- topFilters: Keeps of the marked entries those that no other entry outranks (outranks()), so that each line has one
  entry for each of its marks.
- outranks: Tells whether one entry stands in for another: the same mark on the same line, and deeper for must have
  or higher for must lack, so that a line's entry is its deepest must have and its highest must lack.
- depth: How deep an entry's item lies in its line, counted from the line's top.
- markedFilters: An entry for every marked item that is not a copy, with its mark (filterMark()) and its line, unless
  a marked row above covers it (covered()) or it keeps a lone filter entry instead.
- covered: Tells whether an item's mark is already in the entry of the row above it, or above a copy of it: that row's
  whole branch has the mark, and the row does not keep a lone filter entry of its own.
- byIndex: Sorts entries in the tree's order, by their items' places in `items`.
- entryOf: What an entry of Filters, as filtersOf() gives it, names: a line's deepest item with must have, unless the
  entry is lone, and whether it reads "Full": a building or group marked in full, with more than one row (Req. 24).
  chipName() puts it into words.
- filterMark: The mark an item stands for in Filters: the one all of it shows, else its own.
- keepsOwnFilter: Tells whether a mark keeps an item's lone filter entry: must have on an item that isLoneUnique()
  picks.
- isLoneUnique: Tells whether an item is unique in a line that is not all unique, so it keeps its own entry in Filters
  (Req. 36).
- isUnique: Tells whether data.json counts an item as unique, by its reach (reachOf()).

@ js/model/data/datahandler.js
The Facade over the data: it loads data.json and the language files, unpacks and packs them, and holds the language
  rule, which language the page starts in. It passes on what the other three scripts of js/model/data/ hold, the saved
  settings of storage.js, the address of address.js and attempt() of guard.js, so every script outside js/model/data/
  imports from it alone, and none of them reads a file, the browser's storage or the address (Tests 250, 251).
- useData: Reads data.json and hands its list of civilisations to useCivs(), which gives each civilisation one bit.
- unpack: Turns data.json as stored into the shape used in memory, where overrides and text are kept per language, so
  other languages can be added beside English.
- loadLanguages: Loads every language's file. The tests and the updater need them all.
- loadLanguage: Loads a language's file unless it is loaded already. A visitor downloads only the language shown, not
  all of them.
- load: Fetches a file as text and returns a promise. It uses XMLHttpRequest because, unlike `fetch()`, it also reads
  files when the page is opened from disk, as the tests in CI do.
- localeFile: Returns the path of a language's file, such as `locales/de.json`. Keeps the pattern in one place for
  loading and for the updater's downloads.
- addLanguage: Adds one language file's overrides and text to the data in memory. Used when a language loads, and when a
  test reads back the files the updater would write.
- firstLanguage: The first language of data.json, English, or of the data it is given. The language rule rests on it:
  it is the default (Req. 10), the one whose texts data.json itself holds, and the one the page falls back on.
- hasLanguage: Tells whether a language's file has loaded, so that its texts are in the data.
- preferredLanguage: The language the visitor prefers: the one in the address (`?lng=`), else the visitor's saved
  choice, else the first, English (Req. 10). Shared links and return visits keep their language; first visits are
  English.
- startLanguage: The start language: the preferred language if its file has loaded, else the first. start() gives it
  to the model, and opens the popup `#languageError` when it is not the preferred one.
- pack: Splits the data in memory back into files: data.json with English, and one file per other language. The updater
  writes these, and a test checks that nothing is lost.

@ js/model/data/storage.js
The saved choices, in the browser's storage. `SETTINGS` lists each setting of the Options window with its values, the
  first being its default, so that each is read and stored the same way everywhere. Every read and write goes through
  attempt(), so a browser that refuses its storage, as in a private window, only forgets the choices. datahandler.js
  passes it all on.
- recall: Reads a saved choice from the browser's storage, or null. Remembers the visitor's language and options between
  visits.
- remember: Saves a choice in the browser's storage, or removes it when the value is null. Failures are ignored, as the
  page works without storage.
- recallSetting: Reads a saved setting back as one of its values in `SETTINGS`, or its default when none is saved or
  the saved one is none of them. The model reads Include and Include Regionals with it, script.js Simple UI, and
  optionshandler.js Civ view and Tooltips.
- rememberSetting: Saves a setting's value as text, which recallSetting() turns back into the value. The model saves
  Include and Include Regionals with it, and optionshandler.js Simple UI, Civ view and Tooltips.

@ js/model/data/address.js
The address: `params`, the parameters the page was opened with, such as `?test`, `?update` and `?lng=`, read once, and
  keepInAddress(), the one function that writes it. datahandler.js passes both on.
- keepInAddress: Puts a choice into the address, as `?lng=` for the language, so that a shared link keeps it, without
  a new step in the browser's history. The only function that writes the address, and only model.js calls it;
  failures are ignored.

@ js/model/data/guard.js
attempt(), which runs what the browser may refuse. storage.js and address.js use it, and so do the views, through
  datahandler.js, to read the style sheets, try a selector and capture the pointer.
- attempt: Runs a function and returns null instead of a `DOMException`, the error with which the browser refuses, such
  as storage in a private window, so a refusal never breaks the page. Any other error is thrown again, so that a
  mistake in the code is not hidden.
