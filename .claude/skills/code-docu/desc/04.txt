@ js/tests/run_test.js
Runs the tests in groups and shows the report. Loaded only when the address ends in `?test`.
- merge: Combines the results into one line per test, failed if any of its checks failed, with the first details and the
  window's size. A test may check in several states and languages.
- reportLine: Writes a test's report line, such as "Test 15 failed: ...", from its number, name and details, in the form
  outcome() picks.
- outcome: Picks the form of a report line: passed or failed for a numbered test, and a plain "Failed" for the line
  "the tests ran to the end", which has no number.
- announce: Writes lines of the report to the console, one by one and each starting with `tests:`, where the workflow
  on GitHub reads them from Chrome's log.
- loadFailed: Marks the tests as failed when the page could not load, and says so in the console, so CI never waits for
  a result that cannot come.
- snapshot: Notes the visitor's language, Include, Include Regionals, Simple UI, Civ view, Tooltips and address, and
  the stored language and settings, for restore().
- toStart: Sets the state every group of tests starts from: the page as reset() leaves it, Include unticked, Include
  Regionals ticked, Simple UI and Tooltips on, the civilisations as a list and the first language. So no group depends
  on what the one before it left.
- restore: Puts back the visitor's language, options, view, address and saved choices after the tests.
- runAll: Reads index.html, the style sheets and the scripts as text, then runs the 15 groups of tests one after another
  through runGroup(), in the order TESTS.md lists them; the language tests run once for each language.
- runGroup: Runs one group of tests from the state toStart() sets. If the group throws, as fixtures() does when
  data.json lacks a sample, it fails "the tests ran to the end" with the group's name and the error, and the next group
  runs.
- runTests: Runs the tests and shows their report through runAndPublish(). If the runner itself throws, stopped()
  reports it, so that the run still ends in a result.
- runAndPublish: Keeps the visitor's settings (snapshot()), runs every group, puts the settings back, and publishes one
  numbered line per test.
- windowSize: Names the window's size, such as "1920 by 1080", for the details of a failure and the report's summary.
- numbered: Numbers the tests in the order they first ran, the numbers TESTS.md gives them; the line "the tests ran to
  the end" gets none.
- publish: Marks the page passed or failed, and shows the report, failures first, under a summary with the count, the
  colours and the window's size. For CI it then has announce() write the failed tests, the count and whether they
  passed. Its Close leaves the tests: it opens the page's own address, without `?test`.
- stopped: Marks the tests as failed when the runner itself stops with an error, and says so in the console, so CI never
  waits for a result that cannot come.

@ js/tests/helpers_test.js
Small tools the test files share: recording results, the names of the tests that run in more than one file (`NAMES`),
  finding and measuring elements, reading names as screen readers do, acting like a visitor, and picking sample items.
  Helpers that only one folder's tests use sit in that folder.
- check: Records one test result. Every test reports this way, and each name is one line in the report.
- expect: Records a test that passes when its list of offenders is empty, naming the first few, so a failure points at
  the exact items.
- phone: Tells whether the window uses the phone layout: narrower than 720 px and at least 640 px tall.
- width: Measures the width of the first element a selector finds.
- footerAsWide: Tells whether the footer is as wide as the panes, or the window uses the phone layout, which hides it.
- footerHidden: Tells whether the footer is hidden in the phone layout; in any other layout it holds by itself.
- need: Returns a problem in a list if a condition fails, and an empty list if it holds, so a test can list exactly what
  went wrong.
- same: Tells whether two lists are equal, item by item. Used to compare lists of civilisations.
- codes: Lists the language codes from data.json.
- nodeOf: The row of an item's box and name, from the tree's view, which keeps the elements away from the items.
- twistyOf: The arrow of an item's row, if it has one.
- labelOf: The name in an item's row.
- openTo: Opens every branch above an item, its ancestors(), so that its row is in sight.
- ticked: Tells whether an Options box is ticked, by its `aria-checked`, as screen readers hear it.
- ui: Returns the page's texts in the current language.
- box: Short for an element's `getBoundingClientRect()`: its place and size on the screen.
- keys: Lists every item in the full tree.
- describe: Names an element briefly, such as `button#clear` or a tree row's text, for failure messages.
- rendered: Tells whether an element can be seen: laid out, not hidden, and not text for screen readers only. The
  accessibility checks look at what is rendered.
- everything: Lists every element that can be seen on the page.
- styles: Gets an element's styles and those of its `::before`, `::after` and `::marker` parts, so decorations are
  checked too.
- rgb: Reads the numbers of a CSS colour.
- tone: Names a colour as white, black, green, red or other, loosely enough for light and dark colours.
- drawn: Names the mark drawn on a checkbox, such as "green tick", "red cross" or "white dash", from the borders of its
  `::before` and `::after`, leaving out parts that draw nothing (Req. 3, 14, 23, 26).
- textOf: Reads an element's text as a screen reader would, leaving out parts marked `aria-hidden`.
- tidy: Turns runs of spaces into single spaces and trims the ends.
- nameFor: Works out an element's accessible name much as a browser does: from `aria-labelledby`, `aria-label`, its
  label or its text. Lets the tests check that controls are named (WCAG 4.1.2).
- visibleTexts: Lists the visible pieces of text inside an element. Used to find stray placeholders, and to compare
  names with what can be seen (WCAG 2.5.3).
- keyDown: Sends a key press to an element, as a visitor's keyboard would.
- tap: Clicks an element with mouse pointer events, as a visitor would.
- mustHave: Marks an item must have with a click, as a visitor would.
- mustLack: Marks an item must lack with X, as a visitor would.
- type: Types a text into Find, as a visitor would.
- pick: Chooses a language through the Options window, its menu and OK, as a visitor would.
- reset: Returns the page to its start: Find empty, no marks, every branch closed, the menu and the Options window
  closed, nothing focused. Tests start from here.
- beside: Tells whether Find's message is on one line, right of the box and level with it (Req. 21).
- listed: Lists the civilisations the page shows.
- expected: Lists the names a set of civilisations should show, translated and sorted, to compare with listed().
- itemAbove: Tells whether an item has another item above it, or sits in a group marked `"lines"`, which makes it a unit
  or technology. The tests work this out on their own, apart from the page's code.
- onlyChildren: Lists an item and those below it while each has one item under it, stopping before an item for which
  `stopAt` holds: the rows that opening an item opens, or that a mark on it may pass down to.
- chainOf: The rows that opening an item should open: the item and those below it while each has one row under it
  (onlyChildren()), those with an arrow only. Worked out apart from the page's own [[js/model/itemtree.js#chainOf]].
- outside: Lists the items of a tree outside regional items and all under them: what the tree shows with Include ticked
  and Include Regionals unticked.
- byPath: Finds the item with a path in the tree as it is now, after it was built again.
- onTop: Tells whether an item is the top of its line: a unit or technology right under a building or group. The tests
  work this out on their own, apart from the page's code.
- lines: Lists the items that start a line.
- inner: Tells whether an item is a unit or technology below the top of its line with one item under it, where a mark
  passes down only at the same count (Req. 29, 30).
- fixtures: Picks sample items from the tree: leaves some civilisations have, buildings, line tops, even and uneven
  counts, a line in a group of lines, a building some do without, a lone building and an item with a rival. Found from
  the data, to survive game updates. Each test that uses them picks them itself, after reset(), so no test depends on
  another. It throws when data.json lacks any of the three leaves that most tests mark, so that their group fails "the
  tests ran to the end" instead of checking nothing.
- wait: Waits a number of milliseconds: to hold a long press, and to give a language that is made to fail time to show
  its popup.

@ js/tests/audit_test.js
The accessibility audit: checks the page as it stands against WCAG 2.2 AAA, wherever a test calls it. Its checks are
  Tests 208 to 227, and it checks too that the page does not scroll (Test 29).
- audit: Checks the page as it stands through the checks below, and the focus checks unless asked not to, with the state
  named in each failure's detail. It also checks that the page shows no image, media or picture in its styles (Test 226;
  Rules 9, 22). Called in many states and languages.
- structureChecks: Checks the page's title, its language and every language tag, the language of each language choice,
  its landmarks, its headings (headingChecks()), and that every ARIA reference points to exactly one element (Tests 208
  to 216; WCAG 1.3.1, 2.4.2, 3.1.1, 3.1.2, 4.1.2).
- headingChecks: Checks the headings that can be seen: one main heading, none without text, and none that skips a level
  (Tests 213 to 215; WCAG 1.3.1, 2.4.6).
- unmatched: Lists every id in an `aria-labelledby`, `aria-controls` or `aria-describedby` that no element or more than
  one has, with the element that names it and the count (Test 216).
- controlChecks: Checks that boxes, branches and the language menu say their state, that every control has a name, and
  that the name contains its visible text (Tests 217 to 219; WCAG 2.5.3, 4.1.2).
- colourChecks: Checks the contrast of all visible text, 7:1, or 4.5:1 when large, and of control borders, 3:1 (Tests
  220, 221; WCAG 1.4.6, 1.4.11).
- layoutChecks: Checks 44 by 44 targets, but for links inside a sentence, no page scrolling, nothing sticking out
  sideways, and unjustified text with 1.5 line spacing (Tests 222 to 225 and 29; WCAG 2.5.5, 1.4.10, 1.4.8; Rule 12).
- focusChecks: Focuses every control in turn, only those of the open window when there is one, and checks that nothing
  covers it (Test 227; WCAG 2.4.12).
- visibleCentre: Finds the middle of the visible part of an element's first line, clipped by every scrolling area around
  it, to see what is drawn there.
- focusables: Lists every element that can be seen and reached with the keyboard.
- squash: Lower-cases a text and keeps only letters and digits, for loose comparisons.
- contrastOn: Computes the contrast of a colour, which may be see-through, over the colour behind it.
- contrast: Computes the contrast ratio of two colours, as WCAG defines it, from 1:1 to 21:1.
- luminance: Computes a colour's relative luminance, as WCAG defines it.
- backgroundOf: Works out the colour behind an element by blending its own and its ancestors' backgrounds. Contrast is
  measured against this.
- blend: Blends a see-through colour over the colour below it, to get the colour actually seen.
- rgba: Reads a CSS colour into its red, green, blue and alpha numbers.

@ js/tests/static/scanner_test.js
The scanner that the rules tests read the code with: it reads every script and style sheet of the page as text,
  follows the scripts' imports, and finds the functions of a script by pairing its braces outside its strings and
  regular expressions. It holds no tests itself.
- scripts: Reads every script reachable from `js/script.js`, following its imports, with the path and the names of each
  (importsIn()), and notes which ones load only through a later import, as the tests do.
- importsIn: Lists the imports of a script: each static `import` and `export … from`, with the names it brings in, and
  each dynamic import, which loads later.
- namesIn: Reads the names in the braces of an import as they are exported, without their `as` renamings, so the tests
  can tell which file imports what.
- styles: Reads every style sheet that index.html links, with its address.
- guardScanner: Makes sure the scanner can be trusted before the rules tests use it: it throws when the function finder
  misreads its sample, or when a script has an import that scripts() could not follow, so that the tests fail "the
  tests ran to the end" instead of passing over code they never read.
- importLines: Counts the import lines of a script and its `import(` calls, to compare with the imports scripts()
  followed.
- functionsOf: Finds where every function body in a script starts and ends, by pairing its braces in the blanked text.
- opensBody: Tells whether a brace opens a function's body: after `=>`, or after a parameter list that follows a name
  which is not `if`, `for`, `while`, `switch`, `catch` or `with`.
- blanked: Blanks out the insides of strings, regular expressions and template texts, keeping the code inside `${}` and
  every line break, so that only real braces and parentheses are left to count.
- closing: Finds where a string or regular expression that starts at a place ends, minding escapes and, for a regular
  expression, character sets.
- regexMayStart: Tells whether a `/` after a given character or word starts a regular expression rather than a division,
  so blanked() skips the right text.
- linesOfCode: Counts the lines that are not blank, as Rules 23 and 25 count a function or a file.
- named: Lists the paths of the files a test picks out, the offenders a rules test names.
- testing: Tells whether a file is one of the tests, in `js/tests/`.

@ js/tests/static/rules_test.js
The tests of the rules for the code: comments, CSS and HTML in the scripts, how the scripts load, file names,
  dependencies, the sizes of files, functions and lines, pictures, sounds and animations, and game data in the scripts.
  They read the page's files as text through scanner_test.js; the tests of model, view and controller are in
  layers_test.js.
- sourceTests: Runs the rules tests on index.html, up to the code that Live Server injects, the style sheets and the
  scripts, once guardScanner() has made sure the scanner reads them right: codeTests(), loadingTests(), sizeTests(),
  layerTests() and assetTests().
- codeTests: Tests that index.html, the style sheets and the scripts have no comments, with `//` looked for only outside
  strings (Rule 7), and that the scripts set no styles but numbers for CSS custom properties and build no markup (Rule
  2; Tests 238 to 240).
- loadingTests: Tests that the tests load only when testing and every other script with the page (Rules 4, 6), that no
  two files share a name (Rule 29), and that the code has no dependencies (Rule 14; Tests 241 to 244).
- dependencies: Lists what the code takes from outside the project: a style sheet linked from elsewhere, an import
  that is not relative or leads out of the project, `require`, an `@import` in a style sheet, and a `url()` outside
  the project.
- outward: Tells whether an import is not relative or leads out of the project.
- sizeTests: Tests that no file has over 400 lines of code, no function over 60 and no line of a script over 120
  characters (Rules 23 to 25), and that a top-level function with statements is a `function` declaration (Rule 6;
  Tests 245 to 248).
- longFunctions: Names every function over 60 lines of code, with its line (Rule 23).
- wide: Lists the lines of a script that are over 120 characters (Rule 24).
- widths: Says how many lines of a script are over 120 characters, and from which line, for a failure's detail.
- arrows: Lists the lines of a script where a top-level arrow function opens a block of statements, which should be a
  `function` declaration (Test 248).
- assetTests: Tests that no image in a template has a source, that only the picture look's style rules name pictures
  (Rules 9, 22), that the page plays no sounds (Rule 10), that nothing moves but the loading spin (Rule 11), and that
  the scripts name no civilisation or item of the game (Rule 1; Tests 262 to 266).
- inPictureLook: Tells whether every selector of a style rule is under `.pictures`, the class of the picture look, so
  that Simple UI shows none of its pictures.
- unspun: Takes the loading picture's spin out of a style sheet's text, the only animation allowed, before it is
  searched for others.
- urlsIn: Lists every `url()` in a style sheet, with the selector of its rule and the full address it names.

@ js/tests/static/layers_test.js
The tests that model, view and controller stay apart (Rule 6), read from the scripts' text and imports through
  scanner_test.js, and from the model's items once the other tests have run.
- layerTests: Runs the tests of model, view and controller: pageTests() on the scripts of the page, then importTests(),
  modelTests() and viewTests() on every script.
- pageTests: Tests that only the views touch the page, and that only js/model/data/ touches the address and loads or
  stores data (Tests 249 to 251).
- importTests: Tests that the model imports only the model, and that no view imports a controller (Tests 252, 253).
- modelTests: Tests that no script outside js/model/ and the tests works on the model's sets or imports civsets.js, that
  only page.js observes the model, that model.js shares `subscribe` but not `notify`, that model.js and itemtree.js
  hold no texts, and that no item holds a page element (Tests 254 to 258).
- viewTests: Tests that no view stores data, that only the model saves or restores its own state, Include, Include
  Regionals and the language, and that no view names a mark in a call to its controller (Tests 259 to 261).
- within: Picks the files in a folder.
- reaching: Lists the imports of a file that lead where they should not, as "… imports …".
- importing: Tells whether a file imports a name.
- exporting: Tells whether a script exports a name as a `const`, `let` or `function`.

@ js/tests/static/data_test.js
The tests of the data: that every language has every text and name, and that data.json holds its tree, its items,

- UPDATER: The fields of `source` that the updater needs, each with its check: the address of the game's data and the

- textTests: Tests that every language has all of the page's text, and names every group, item and civilisation (Tests

- missing: Lists the names a language lacks in one part of its texts, such as `ui` or `civs`.
- dataTests: Runs the checks of data.json: its tree, its items, its texts and its source.
- treeTests: Tests the tree in data.json: every item once, only known fields, `"unique"` and `"lines"` only on groups
  and `"own"` only on items, and `"excludes"` and `"replaces"` naming other items of the tree (Tests 267 to 272).
- nodesOf: Lists every node of a tree, those under the others included.
- misflagged: Makes the question whether a node holds a flag wrongly: as anything but `true`, or on the wrong kind of
  node.
- linksOf: Lists the items a node's `"excludes"` or `"replaces"` names, one or several.
- itemTests: Tests every item of data.json: its availability names only known civilisations, it has an icon, and it is
  common, regional or unique; and each entry of `extras` is a tree item with a name number and known civilisations,
  stored as the updater writes it (Tests 273 to 277).
- knownCivs: Tells whether an availability, `"all"` or a list under `has` or `lacks`, names only known civilisations.
- kept: Tells whether data.json stores an extra's availability and icon as the updater makes them of it, through
  fromExtra().
- alike: Tells whether two values are equal, by their JSON.
- textDataTests: Tests the texts in data.json: counted texts with an "other" form, the same placeholders in every
  language, and overrides of known names (Tests 278 to 280).
- holes: Lists the placeholders of a text, such as `{n}`, once each and sorted, to compare a translation with English.
- sourceDataTests: Tests that the source the footer names, with its game update's number and address, the updater's
  source, the tool texts and the ignore list are filled in (Tests 281 to 284).
- unfilled: Lists the fields of the source that their checks, in `FOOTER` or `UPDATER`, find empty.

- marking: Tests marking by click, X, the menu key (menuKey()) and Space, what screen readers hear, the civilisation

- gestures: Tests that a long press with a finger marks must lack, that a right-click clears it and then marks it again,

- rightClick: Right-clicks a row as a visitor's mouse would, with pointer events and the `contextmenu` that follows, and

- chipMarks: Names the mark drawn on each filter button, sorted, such as "green tick" and "red cross".

@ js/tests/behaviour/lines_test.js
The tests of lines: how a mark passes down a line and up to the items above it, and what marking a unit or technology
  opens.
- lineTops: Tests that marking the top of a line passes the mark down only to the items with the same civilisations,
  must have or must lack, that marking it again clears it, that marking a line's last item marks the line before it
  with one filter button, named after that item, and that must lack on the top then clears the must-have marks below it

- parents: Tests that must have passes up but never to a building, which then shows a dash, and that an item can be must
  lack while everything under it is must have (Tests 41, 43, 21, 7 and 5; Req. 4, 26, 34).
- lines: Tests that marking a closed unit or technology opens it to its first fork or its end (Test 59; Req. 28), then
  runs evenLine(), unevenLine() and beyond().
- evenLine: Tests an item below the top of a line whose item under it has the same civilisations: must have on it passes
  up to the items above it and down while the civilisations stay the same, and no further (Tests 41, 39 and 27; Req.
  29, 30, 34).
- unevenLine: Tests an item below the top of a line whose item under it has other civilisations: must lack on it passes

- sameCivs: Lists the items of a line, from an item down while each has one item under it that is not a group, that have
  the same civilisations as the item: those a mark on it passes down to (Req. 29, 30).
- marked: Lists the marked items, leaving out the copies of shared rows, which carry their original's mark.

  cannot be marked, by a click or by the model's toggleMark() itself (Tests 48 to 50).
- standIns: Tests an item that replaces others, such as the Pasture and the Farm: a row they share (sharedRow()), must
  have on either greying out and closing the other (shuts()) until it is cleared, and, with Include ticked, the rows it
  borrows (borrowedRows()) and what each variant greys out (variants()) (Test 57; Req. 37).
- sharedRow: Tests that marking a row that an item holds of what it replaces marks it in both buildings, opens nothing
  in the other, and makes one plain filter button (Tests 52 to 54).
- shuts: Tests that must have on one item greys out and closes the other, which then can be marked neither by a click
  nor by X, and whose arrow does not open it (Tests 46, 48, 55 and 56; Req. 37).
- borrowedRows: Tests that each item that replaces buildings holds, as copies, exactly their common and regional rows,
  but for those under `"own"`; a unit or technology it replaces lends it none (Test 58).
- variants: Tests that must have on each variant greys out exactly its alternatives, as alternativesOf() works them out
  from data.json (Test 55; Req. 37).
- ownKeys: Lists the items marked `"own"` and everything under them, which items standing in for theirs never show.
- alternativesOf: Lists the items that marking an item must have should grey out, from data.json alone: the items it
  names, the items that name it, and those that name what it names (Req. 37).
- side: Lists an item and everything under it but a given item and what is under that: what an item greys out of the
  branch it excludes, when it sits inside that branch.
- greyedItems: Lists the items whose rows are greyed out for screen readers, by `aria-disabled`.
- greyed: Tells whether an item's row is greyed out both for screen readers and for the eye.

@ js/tests/behaviour/finding_test.js
The tests of Find: what it highlights, opens and counts, and that it drops a match that a mark greys out.
- finding: Tests that Find highlights exactly its matches, in yellow, opens the branches down to them and counts them
  beside the box, drops a match once a mark greys out its branch (dropsGreyed()), says when nothing matches, and clears
  its count when emptied (Tests 74 to 80; Req. 20, 21).
- dropsGreyed: Tests that Find drops a match once a mark greys out its branch: marks a sample's rival, or that rival's
  own, until a branch is closed and greyed out, searches for an item in it without the mark, marks again, and checks
  that the match loses its yellow and that the count beside Find agrees (Test 79).
- yellow: Tells whether a colour is yellow: red and green high, blue clearly lower (Req. 20).
- found: Tells whether an item's row is highlighted as a match of Find.
