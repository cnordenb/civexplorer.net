@ (title)
This document explains the code of AoE2 Civ Explorer. Each folder is a chapter, and each file in it a subchapter. In the
  subchapters on scripts, each function defined at the top level of its script is a section, numbered after its chapter
  and subchapter, so the fourth section of the first file in chapter 4 is 4.1.4. A section gives the lines the function
  takes up, says what it does and why, and lists the functions that call it and the functions it calls. A function
  handed on to be called later, such as an event handler, counts as called by the function that hands it on. Helpers
  defined inside a function are part of that function's text.
"Exported" marks a function that other scripts import, and "internal" one that only its own script uses. The subchapters
  on the page, its style sheets and the data are split into parts in the same way, each with its lines. Rules and
  requirements are those of RULES.md and REQUIREMENTS.md.
Every name of a folder, a file or a function links to its chapter, subchapter or section, and the page header always
  names the chapter and the subchapter. The contents list the chapters, each with its subchapters indented under it. The
  four UML diagrams after the contents show how the parts and the scripts use each other, and the index at the end
  lists every chapter, subchapter and function in alphabetical order.

@ (uml)
Four class diagrams show how the scripts use each other. The first, the one in MAINTAINER.md, shows the code in its
  three parts, model, view and controller, file by file; the other three show the scripts of each part, function by
  function. In each, an arrow points from what uses to what is used. No arrow crosses or touches another, or runs under
  a box or a label: making this document checks every diagram for it, and stops if one does. Each box and each name in
  a box links to its chapter, subchapter or section.

@ (uml overview)
Each box is a folder, with the scripts in it and in its subfolders, each named from the box's folder, such as
  data/datahandler.js; `start` is js/, whose script.js starts the page, and the box of the tests names its four folders
  of tests in place of their scripts. Each arrow points from a part to a part whose scripts it uses, and says what for.
  The tests use all three parts as well; those arrows are left out, because with them some arrows would have to cross. A
  box links to its folder's chapter, and a script to its subchapter.

@ (uml model)
The scripts of js/model/ and js/model/data/, each with its functions and objects: `+` marks what a script exports, and
  `-` what it keeps to itself. The line under a script's name gives its role: its part in model, view and controller,
  which MAINTAINER.md explains, what it reads, or "module". An arrow points from a script to a script of the model that
  it imports; what the scripts use of the view and the controller is in the overview.

@ (uml view)
The scripts of js/view/ and js/view/pictures/, each with its functions and objects, drawn as in the diagram of the
  model: `+` for what a script exports, `-` for what it keeps to itself, its role under its name, and an arrow to each
  script of the view that it imports.

@ (uml controller)
The scripts of js/controller/, each with its functions and objects, drawn as in the diagram of the model. None of them
  imports another, so there are no arrows: what they use of the view and the model is in the overview.

@ index.html
The page's structure, and all of its HTML (Rule 2). It holds no text of its own: the scripts fill in every word in the
  chosen language, and copy its templates instead of writing HTML.
- [Head 1-20]: Sets the language, character set, viewport, light and dark colour schemes, title and description, and
  what link previews show: the `og:` tags give a title, a description, `assets/images/preview.jpg` and the page's
  address. It links base.css, pictures.css and script.js, as a module. It names no tab icon: browsers fetch
  favicon.ico from the main folder by themselves.
- [Loading screen 22]: The screen shown without Simple UI until every picture has loaded, with its text. setLoading()
  adds the turning picture from its template.
- [Header 23-26]: Holds the title twice: the full sentence of Req. 2 for Simple UI, and "Civ Explorer" for the pictures
  (Req. 0). Then the cogwheel Options button (Req. 6), a text character with a hidden label. Hidden until the page
  starts.
- [Messages 27-28]: A noscript line for browsers without JavaScript, and a load error shown in English if data.json
  cannot be loaded, so a visitor is never left with a blank page.
- [Tree pane 29-50]: The start of the content, then the left pane, in the order of Req. 3: heading, Clear, Expand all
  and Collapse all, the Find field with its label, clearing cross and live match count, the must have and must lack
  legend, and the empty tree.
- [Civilisations pane 51-64]: The right pane (Req. 4): heading, live count, the Filters list (Req. 22), the civilisation
  list and the hint shown when it is empty. It scrolls on its own, so the page never does (Rule 12).
- [Footer 65-66]: Names and links the data source and the game update the data is from, which links its notes (Req.
  5), then Microsoft's notice, in English, with links to its rules and to the project. The code writes the sentence
  around the links.
- [Options window 67-83]: A dialog (Req. 7, 8, 32): title, the language label, button and list, then the settings:
  Simple UI, Include Unique and Universal with its description, Include Regionals, Civ view and Tooltips; and Cancel and
  OK.
- [Language popup 84-87]: The popup that says a language could not be loaded: a modal dialog with the role
  `alertdialog`, so screen readers read its message at once, and an OK that closes it. showLanguageError() opens it.
- [Report window 88-96]: A dialog for the reports of the tests and the updater: title, live status, result list,
  download links and Close. Always in English, so it is marked `lang="en"`.
- [Templates 97-106]: Markup for tree rows, Filters buttons, civilisations, whose links open in a new tab, the loading
  picture, the icons of civilisations and of the tree, language options, report lines, downloads and the scroll bar. The
  code copies these instead of writing HTML (Rule 2).
- [Tooltip 107]: The note that follows the mouse without Simple UI: over the tree, over every control, each naming its
  text with `data-tip`, and over a link, with its address. Hidden otherwise.

@ css/base.css
How the page looks with Simple UI, and its layout either way: colours, sizes and layouts for big and small screens, in
  light and dark mode. Every rule with a picture or a font is in pictures.css instead.
- [Colours 1-33]: Named colours for light mode, redefined for dark mode: text, lines, marks, hover, Find's yellow, the
  green and red of the marks, and the dark box behind the white dash; and the 44-pixel target size and the font. The
  tests measure their contrast.
- [Base 34-46]: Box sizing, `hidden` that always hides, a full-height page that never scrolls (Rule 12), the system font
  with 1.5 line spacing (WCAG 1.4.8), a 3 px focus outline (WCAG 2.4.13), and a class that hides text from sight but not
  from screen readers.
- [Header and language 48-66]: Lays out the title and cogwheel, and in the Options window the language label, its button
  with a turning chevron, and the list of languages, where the current one is marked with a bar and bold.
- [Panes 68-83]: Two panes side by side from 720 px wide; below that they share a phone's height, and the footer is
  hidden. Each pane's head stays in place while its list scrolls.
- [Controls 84-101]: Buttons and the Find field are at least 44 by 44 px (WCAG 2.5.5), with visible borders and a hover
  colour. Find's message keeps its column, so the box never changes size while typing (Rule 18). The legend, and the
  scrolling lists.
- [Tree 103-121]: Indented rows with dotted guide lines, 44 px rows, turning arrows, pressed and greyed-out rows, and
  found rows in yellow with the light colours (Req. 20) whatever the colour scheme.
- [Check boxes 122-140]: Marks drawn with borders (Req. 14, 23, 26): a green tick, a red cross, and a white dash on a
  dark box, in system colours when colours are forced. A setting that is on in the Options window shows the green tick.
- [Names and views 141-145]: Hides Civ view and Tooltips, which only the pictures use; makes top-level and group names
  bold; keeps counts on one line at the right; and draws focus rings inside rows.
- [Filters and list 147-163]: Filters as a wrapping row of rounded chips under the pane's head, the civilisation list in
  columns that never split a name, the empty hint and the footer.
- [Dialogs 165-188]: Size, padding, border and backdrop of the Options and report windows and of the popup, which is
  as wide as its message. The Options window is a grid of fixed height, so opening the language list never resizes it
  (Rule 18); only the report's list scrolls.
- [Small screens 190-201]: On short screens everything scrolls as one, as at 400% zoom (WCAG 1.4.10); on narrow ones the
  padding and the tree's indent shrink.
- [Test helper 203-204]: The wider text spacing the tests apply (WCAG 1.4.12). Used only while testing.

@ css/pictures.css
How the page looks without Simple UI. Every rule here that shows a picture starts with `.pictures` or `html.pictures`,
  so Simple UI turns them all off (Rules 9, 22), and picture addresses go from this folder, as `../assets/`. The
  `[data-assets="4k"]` and `[data-background]` rules pick the pictures for the screen.
- [Parchment and cursors 1-24]: The parchment behind the page, fitted so the content lies inside its frame on any
  window, in the four sizes; the ink, gold and serif font the other rules name; the sword and the pointing hand as
  cursors, the `_x2` ones drawn at two thirds of their size, at `1.5x` in `image-set`, so they are as large as the `_x1`
  ones.
- [Header and footer 25-47]: The footer's colours, the title in its frame with the short title, the load error, and the
  Options button from its three-state sheet.
- [Fonts 48-57]: Georgia, Times New Roman Bold and Trajan Pro Bold from `assets/fonts/`, under their own names, trying
  the installed copy first. Only rules for the pictures use them, so Simple UI never downloads a font.
- [Text buttons 58-67]: Every button with words, but those of the report and the language box, shows the button picture,
  normal, under the mouse or pressed, with its ends drawn apart so it can be any width.
- [Loading screen 69-72]: The screen that covers the page while the pictures load, and its turning picture, the only
  animation, which stops with reduced motion (Rule 11).
- [Boxes and radio buttons 74-90]: Check boxes from their sheet, a row for each state and a column for normal, under the
  mouse and pressed, with a black dash; Tooltips and the Civ view radio buttons, shown only here.
- [Frames 91-98]: The 9-slice frames of the two panes, and their fonts and colours.
- [Options window 99-114]: The window's frame, measured to fit around the same window as with Simple UI, with its
  contents 60 pixels from the frame's sides, or 120 of the screen's own pixels on a 4K screen (`--pixel`), and the
  settings lit under the mouse.
- [Language box 115-146]: The language menu as the game's combo box: its picture, 219 by 35 pixels at the right of its
  row, with the language's name and, at its right end, the arrow from its atlas, pointing down while the list is closed
  and up while it is open, normal, under the mouse or pressed, and 35 by 28 of the screen's own pixels on a 4K screen.
  The list lies over the settings below the box, as wide as it and seven languages high, in the box's colours, and snaps
  to whole languages; the chosen language is red and the one under the mouse teal. Its scroll bar lies over it.
- [Options on tall windows 147-160]: On windows at least 588 pixels high, the parchment behind the window, OK and Cancel
  in its corner, and the title on its ribbon.
- [Tree 161-182]: The tree's colours, found rows in amber, the rows' icons from the four atlases with an outline by kind
  and reach as `colour_key.csv` says, and greyed-out icons.
- [Tools 183-191]: Filters chips, no legend, Find first, and Clear and Expand all as two buttons that share the pane's
  width; the buttons of the Options window and of the popup have the button picture's shape.
- [Find box 192-209]: Find's field in its 9-slice frame, 325 px wide, with the search picture while empty and the
  clearing cross while not; the hidden label and Include's hidden description.
- [Tooltip 210-214]: The tooltip's place, set by the script as numbers, 32 pixels from the pointer as both cursors are
  32 pixels large, and its parchment look.
- [Civilisations 215-230]: The civilisations' icons from their atlas, and the tiles, six to a row, each with its icon
  and its name in Trajan Pro.
- [Scroll bars 231-262]: The game's scroll bars: the browser's are hidden, room is kept for the bar, and the bar is
  placed, sized and drawn from its arrows, body and knob, each from its sheet, as [[js/view/pictures/scrollbars.js#fit]]
  sets them. The language list's bar has the combo box's arrows instead, centred on it, and its arrows and knob always
  show their first picture.

@ data.json
All of the page's data, in English: the civilisations, the tree, who has each item, its icon and the page's texts.
  useData() reads it at start-up, and the updater writes it through pack() and toJson(): short objects and lists on one
  line, the rest indented by two spaces. The other languages' texts are in `locales/`, one file each, laid out like the
  `overrides` and `text` here.
An item is named by its English name throughout: the tree, `availability`, `pictures`, `extras` and `text.items` use the
  same names as keys.
- source: Where the data comes from: aoe2techtree.net and its data address, `helpOffset` (taken from an item's help
  string number to find its text, in localName()), the game update the data is from, with the address of its notes,
  which the updater reads and the footer links, and Microsoft's notice with the rules and the project it links.
- languages: Every language by its code, with its name in itself, its language tag, and whether its words are spaced and
  its hyphens at line ends are merged. English comes first.
- civs: The civilisations, in the order whose bits the sets use. A set is a number with one bit per civilisation
  (bit()).
- icons: Where the pictures are: the file names of civilisations that differ from their names, and the folder of the
  tree's icons.
- icons.groups: The icon of each top-level group, by kind and picture.
- icons.atlas: For each kind, the pictures in its atlas, which cellOf() places by file name, and cellIn() in the tests
  too.
- tree: The tree as nested objects: `{"group": …}` for a top-level group or a group in a building, `{"item": …}` for an
  item, with `kids` for what is under it and the flags `own`, `lines`, `excludes` and `replaces` where they belong.
  rebuild() reads it.
- availability: Who has each item: `"all"`, `{"has": […]}` or `{"lacks": […]}`, whichever is shortest
  (availabilityOf()). setOf() turns it into a set.
- pictures: Each item's icon: its kind, its picture in that kind's atlas, and its reach, common, regional or unique,
  which Include Regionals and the outlines use.
- ignore: Names on aoe2techtree.net that the updater does not report as new items.
- extras: Items aoe2techtree.net does not show in its tree, with their kind, picture, reach, name number and
  civilisations. fromExtra() turns each into availability and a picture.
- overrides: Names to use instead of the game's own, where it gets one wrong.
- tools: The texts of the tests' report and of the updater, in English only, with `{}` placeholders that fill() fills
  in.
- text: The page's texts in English, in four parts.
- text.ui: The page's own texts, by the name `data-text`, or for a tooltip `data-tip`, gives in index.html, counted ones
  as `{"one": …, "other": …}` for plural().
- text.groups: The name of each group.
- text.civs: The name of each civilisation.
- text.items: The name of each item.

@ locales/de.json
The German texts. Every other language has a file like it in `locales/`, which the page loads when that language is
  chosen (localeFile()) and the updater writes. It holds the two keys of data.json that differ by language, with the
  same keys inside.
- overrides: German names to use instead of the game's own.
- text: The page's texts in German, in the same four parts as data.json's `text`.
- text.ui: The page's own texts.
- text.groups: The name of each group.
- text.civs: The name of each civilisation.
- text.items: The name of each item.
